## 2026-11-19 v2.0 打通

**音频采集（第 4 步）**：ALSA 常开录音，每 3 秒一段，峰值门限判定人声。实测安静峰值约 1000、说话 3237~6406，门限最终定 900。麦克风走板载 RK809 + I2S，和 USB 摄像头不抢资源。

**云端接入（第 5 步）**：交叉编译 openssl 4.1.0 + curl 8.23.0，静态链接避免和板载 openssl 1.1 冲突。四个坑：openssl 用 `--cross-compile-prefix`、curl 要 `--without-libpsl`、链接要 `-ldl`、CA 路径要自己给。

**语音识别绕了四圈**：`qwen-audio-3.0-asr-flash` 报 format empty，`fun-asr-flash` 没权限，`qwen3-asr-flash-realtime` 报 500，`/audio/transcriptions` 404。最后试 `qwen3-omni-flash`，一次就通——名字带 asr 的反而不能用这套接口。

**端到端跑通（第 6 步）**：五条线程同时跑，说一句"桌上有什么"，走完 ASR → 意图判断 → 抓帧 → 视觉模型 → 回答。三个调优：门限 300 提到 900（噪声会被识别成"嗯"）、过滤语气词、回答限三十字（要念出来）。

**源码重构**：分到 `src/`、`include/`、`third_party/`，迁到 Makefile，带自动头文件依赖。

**还差**：TTS 等耳机到货。

## 关键结论（来自 README 实测，不按日期）

- **帧率锁在 15.1fps 是摄像头固件的问题**，不是代码。七步排查：硬件声明支持 30fps → 驱动读回 1/30 → USB 是 480Mbps 高速链路 → `dmesg` 无带宽错误 → 降分辨率到 640x480 帧率不变 → 换采集方式不变 → 结论落在固件
- **稳定性**：32.8 分钟连续跑，393 个采样点，推流丢帧 0，RSS 11616KB → 12148KB 后 28 分钟不动
- **CPU**：720p 单核约 61%，`drop_preview` 累计 1277（预览跟不上就丢自己的帧）；480p 单核 47%，`drop_preview` 0
- **`stb_image` 解 MJPG 要补 432 字节 DHT 表**，否则解不出来
- 已知限制：帧率固件锁死、慢客户端可能被误踢、软件解码吃单核四到六成、预览无双缓冲会撕裂、没有音频
