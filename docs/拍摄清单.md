## 一、照片（手机拍，3 张）

| 文件名 | 拍什么 | 要点 |
|---|---|---|
| `docs/img/board-overview.jpg` | 板子 + 摄像头 + 屏幕全景 | 桌面收拾干净，背景别太乱；屏幕要能看到预览画面；自然光，别开闪光灯 |

## 二、截屏（电脑上截，4 张）

前提：板子已经跑起来

```bash
amixer -c 0 sset 'Capture MIC Path' 'Main Mic'   # 可选，只看视频可以不设
/root/capture /dev/video9 MJPG /root/frame 100000
```

| 文件名 | 截什么 | 怎么产生 |
|---|---|---|
| `docs/img/mjpeg-stream.png` | 浏览器里的推流画面 | 电脑浏览器打开 `http://172.70.1.33:8080/`，等画面稳定后截**整个浏览器窗口**（带地址栏，证明是真访问） |
| `docs/img/status-json.png` | `/status` 的返回 | 终端里执行 `wget -qO- http://172.70.1.33:8080/status`，截**终端窗口**，命令和输出都要在 |
| `docs/img/boot-log.png` | 程序启动日志 | 串口终端里程序刚起来那几行 `[NET]` `[AUD]`，截终端窗口 |
| `docs/img/dmesg-uvc.png` | 摄像头被识别 | 串口里执行 `dmesg \| grep -i uvc`，截终端窗口 |

**截屏注意**：窗口用深色主题更清楚；把无关窗口关掉；串口窗口字体调大到 14 以上，否则 README 里看不清。

## 三、原始数据（命令生成，4 个文件）

这些比截图更有说服力，因为别人可以下载下来自己看数字。

| 文件名 | 生成命令 |
|---|---|
| `docs/bench/status.json` | `wget -qO- http://172.70.1.33:8080/status > status.json` |
| `docs/bench/dmesg-uvc.log` | `dmesg \| grep -i uvc > dmesg-uvc.log` |
| `docs/bench/boot.log` | 程序启动到稳定运行的头 40 行 |
| `docs/bench/soak-rss.csv` | 压测时的 RSS 采样，见下一节 |

### 压测数据（可选，但最能打）

```bash
# 板子上，跑 30 分钟，每 5 秒记一次
( while true; do
    echo "$(date +%H:%M:%S),$(wget -qO- http://127.0.0.1:8080/status)"
    sleep 5
  done ) > /root/soak.log
```

跑完把 `/root/soak.log` 拉下来改名 `docs/bench/soak-rss.csv`。

**这条数据能证明什么**：RSS 从启动到 30 分钟后不变，说明没有内存泄漏。README 里那句「393 个采样点 RSS 不增长」就是从这里来的。
